Code Walkthrough

训练 step 后把新参数同步进 vLLM serving engine

结论先放前面：现在设计和代码都按“同一个模型、每个 optimizer step 后热同步权重、下一轮 rollout 使用新参数”走。 主路径不是写 checkpoint 再让 vLLM load，而是 vLLM 原生 Weight Transfer。checkpoint artifact 只保留为恢复、审计和 fallback。

是否能切版本

能。nano-rl 用 WeightMeta.version_id 做控制面版本，vLLM engine 用 native weight update 接收同一个模型的新 tensor。

同卡/同机

shared-GPU replica 走 ipc，数据面是 CUDA IPC handle，跨 Ray actor 进程传递，不走 ckpt reload。

分卡

rollout-only 或 trainer/rollout 分卡 replica 走 nccl，rank0 和 vLLM workers 建 NCCL 通信组后广播权重。

防 stale

require_weight_sync=true 时缺少 vLLM Weight Transfer 能力会 fail fast，不会悄悄用旧权重继续 serving。

一句话答案

每次 train step 结束后，driver 先拿到新的 WeightMeta(version_id=N) 并注册； 随后调用 _sync_native_vllm_weights()，按 replica 的 WeightShardSource 选择 IPC 或 NCCL， 让 trainer 进程把当前 model.named_parameters() 直接同步进 vLLM rollout actor。 只有同步完成后，后续 activate_weight() 和 registry ack 才会把 version N 标成 rollout active。

代码锚点： ray/training.py， fsdp2_backend.py， vllm_backend.py， actors.py。

step 级链路

1. train step 完成。 RayTrainingLoop._run_train_step() 训练、导出并调用 WeightRegistryActor.register()。

2. 同步新 tensor。 _sync_native_vllm_weights() 在 activation ack 之前触发 trainer-to-vLLM native sync。

3. 再激活版本。 _activate_weight_for_rollout() 仍负责 pause、begin_activation、replica ack 和 resume。

控制面

控制面不传大 tensor，只传版本、计划、lease 和 ack。核心对象是 WeightMeta 和 WeightTransferPlan。 WeightTransferPlanner 根据 GPU 拓扑为每个 rollout replica 生成一个 WeightShardSource。

source kind native backend 含义
shared_gpu_reshard ipc rollout TP group 所在 GPU 同时也是 trainer rank GPU。数据面用 CUDA IPC handle 跨进程共享 tensor。
artifact_pull nccl rollout-only GPU 没有 trainer-resident 权重。当前热同步路径用 NCCL 从 trainer rank0 广播到 vLLM workers。
ray_object_ref 调试路径 保留给 mock、小模型或实验；真实大模型不把 Ray object store 当主权重总线。 
registered = self._call("weight-registry", "register", exported)
self._sync_native_vllm_weights(registered, trainer_leases)
...
active = self._activate_weight_for_rollout(registered)

数据面

IPC: 同机同 GPU / shared-GPU

driver 对一个 shared rollout replica 会调所有 trainer ranks 的 TrainerRankActor.sync_weights_to_vllm(..., transport="ipc")。 FSDP ranks 在各自进程里调用 IPCWeightTransferEngine.trainer_send_weights()； vLLM 的 IPC engine 通过 CUDA IPC handle 跨进程拿 tensor，rank0 负责把合并后的 update 发给 rollout actor。 

if transport == "ipc":
    participants = all_trainer_ranks
    IPCWeightTransferEngine.trainer_send_weights(
        iterator=_named_parameters_for_weight_sync(model),
        trainer_args=IPCTrainerSendWeightsArgs(send_mode="ray", llm_handle=rollout),
    )

NCCL: 分卡 / rollout-only

NCCL 路径由 trainer rank0 开一个 trainer-vLLM worker 通信组。 rollout actor 先进入 update_weights() 等待接收；trainer 侧随后调用 NCCLWeightTransferEngine.trainer_send_weights() 广播每个参数 tensor。 

init_info = {
    "master_address": local_ip,
    "master_port": free_port,
    "rank_offset": 1,
    "world_size": 1 + inference_worker_count,
}
rollout.init_weight_transfer_engine(init_info)
update_ref = rollout.update_weights(update_info)
NCCLWeightTransferEngine.trainer_send_weights(iter(parameters), trainer_args)
ray.get(update_ref)

vLLM backend

VllmRolloutBackend 现在不只会构造 vllm.LLM，还把 native weight update lifecycle 暴露给 Ray actor： init_weight_transfer_engine、start_weight_update、update_weights、finish_weight_update。

engine 构造时会传 WeightTransferConfig(backend="ipc"|"nccl")。如果本地 vLLM 版本没有这个 API， 且 require_weight_sync=true，会直接报错；这比“继续用旧权重 rollout”安全。 

weight_transfer_config = WeightTransferConfig(backend=backend)
vllm.LLM(model=..., tensor_parallel_size=..., weight_transfer_config=weight_transfer_config)

配置入口

新配置在 rollout.vllm 下： 

rollout:
  backend: vllm
  vllm:
    weight_sync_backend: auto
    require_weight_sync: true

auto 在 Ray placement 时按 replica 拓扑落成具体 backend： shared replica 为 ipc，rollout-only 或分卡 replica 为 nccl。 也可以显式写 ipc、nccl 或 none。

版本一致性

同步完成不等于控制面已经对外宣布。vLLM actor 在 finish_weight_update() 后把该 version_id 记入 _synced_weight_versions；随后 activate_weight() 只更新 backend active metadata，不再走 checkpoint hook。所有 rollout replicas ack 后， WeightRegistryActor 才把版本推进到 ACTIVE_GLOBAL。

关键点 下个 step rollout 取的是 registry 里 active 的新 version；生成出的 SampleRecord 继续携带 policy_version 和 checksum。

边界

当前工作区安装的 vLLM 是 0.8.5，没有 vllm.distributed.weight_transfer。 代码已经按新 API lazy import 和 fail-fast 接好，真实 GPU smoke 需要升级到带 Weight Transfer 的 vLLM。

FSDP 多 rank 场景里，IPC 路径要求所有 trainer ranks 同步参与；NCCL 路径要求 rank0 能提供 vLLM 可加载的完整参数迭代器。 这些都是数据面约束，不是 registry 或 checkpoint 能绕开的控制面问题。

验证

已补的单测覆盖三件事：vLLM backend 暴露 native update lifecycle；Ray training loop 在 activation ack 前触发 native sync； IPC 路径所有 trainer ranks 参与，NCCL 路径只由 rank0 广播。
