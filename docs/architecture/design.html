架构总览

nano-rl v0.1 的核心目标是做一个“小而全”的 RL 框架：trainer 后端目标是 PyTorch FSDP2， rollout 后端目标是 vLLM，执行层固定为单机 Ray-native actor runtime。控制器拥有 loop 语义； trainer、rollout、reward、queue、weight registry 和 metrics 都是可替换后端或服务边界。

YAML-first Ray-native FSDP2 trainer vLLM rollout policy_version accounting bounded staleness single-machine v0.1

Control plane

main.py 读取 YAML，校验并归一化成 LaunchConfig。Ray Driver 通过 RayClusterController 初始化 runtime：address=auto 先连已有 cluster，失败后创建本机 cluster，再创建 ControllerActor 并由 controller 驱动模式 FSM、train window、rollout 节奏和故障恢复。

Resource plane

用户 YAML 只填写数量：rollout_only_gpus、shared_gpus、rollout DP/TP 和 trainer ranks。LaunchConfig 展开 deterministic gpu_plan，由 CPU-only GpuLeaseManagerActor 管理 active-role lease。

Data plane

rollout 样本通过 Ray ObjectRef 进入 SampleQueueActor，trainer 通过 reservation 消费。权重通过 WeightMeta 和 WeightTransferPlan 指向 backend loader 可读取的模型或 checkpoint artifact；默认不把大权重放进 Ray object store。

Execution backends

RayActorGraphLauncher 已能按 RayLaunchPlan 创建 actor graph；启动真实 graph 前会先 connect-or-create Ray cluster。Ray actor wrappers 已接入 vLLM / FSDP2 backend adapter，RayTrainingLoop 会在 graph 启动后串接 rollout、reward、sample queue、trainer、weight registry 和 weight activation。run.start_ray_actors 控制 train 路径是只输出 plan，还是实际启动 Ray actor graph 并执行训练循环。

SVG 组件关系图

图中实线表示控制或数据调用关系。rollout 与 trainer execution actors 是独立故障域；它们通过 role-scoped logical resources 放置，并在执行 CUDA 前校验 GpuLeaseManagerActor 发放的 lease token。

SVG rollout 全流程图

下面把一次 rollout 从 prompt 分发到样本入队、训练消费、权重发布和全局激活串起来。fully_sync 下所有 rollout GPU 都来自 shared_gpus， 每轮 rollout 后整体切 train；standalone_hybrid 下只 drain 占用 shared_gpus 的 rollout replicas， rollout_only_gpus 对应的 replicas 在背压与 policy lag guard 下继续生成。

运行模式

用户 YAML mode 内部 canonical mode GPU topology rollout/train 语义
collocated fully_sync rollout_only_gpus=0；全部 rollout GPU 都来自 shared_gpus。 全局 barrier：同一版本权重完成 rollout 后，所有 rollout replicas drain，shared GPU lease 切给 trainer，再发布下一版本。max_policy_lag=0。
disaggregated standalone_hybrid 同时存在 rollout_only_gpus 与 shared_gpus；示例为 4 张 rollout-only GPU、4 张 shared GPU。 rollout-only replicas 持续生成；shared replicas 在训练窗口 drain 后释放 lease 给 trainer ranks。允许 bounded staleness，例如 max_policy_lag=2。

sync / async 不是用户入口别名；fully_sync / standalone_hybrid 也不能直接作为用户 YAML mode。 这些内部名只应该出现在 resolved config、日志和 FSM 中。

组件设计

main.py 与配置加载

用户入口只负责读取 YAML、处理 run.intent、归一化 mode、校验 artifact 和资源拓扑、将 resolved config 写入被 git ignore 的 .nano_rl/resolved-config.json，并生成不可变 LaunchConfig。训练参数不应拆成命令行覆盖面。

Ray Driver

负责 Ray connect-or-create、单机资源校验、placement group 规划和创建 ControllerActor。runtime.ray.address=auto 先尝试连接已有 cluster；连不上时创建带 resolved custom resources 的本机 Ray cluster。显式非 auto address 保持 fail-fast。v0.1 不加入 Kubernetes、Slurm、SSH 或多节点 Ray launcher。

ControllerActor

唯一 loop 语义 owner。它决定何时发 prompt、何时开 train window、何时限流、何时进入 degraded 或 paused，并统一解释 actor 异常为 health event。

Mode FSM

维护 BOOTSTRAP、FULLY_SYNC_ACTIVE、STANDALONE_HYBRID_ACTIVE、DEGRADED_SYNC、PAUSED 和 STOPPED。FSM 只处理 canonical mode。

GpuLeaseManagerActor

CPU-only actor，管理每张物理 GPU 的 active role、holder、lease epoch 和失败状态。rollout/train actors 可映射到同一张 shared GPU，但执行 CUDA 前必须校验 lease token。

Lease toggle

默认策略是 swap_on_toggle，只对 shared_gpus 启用。rollout -> train 时 shared replicas drain、flush sample、释放 vLLM/KV cache，然后 lease 切给 trainer ranks；rollout-only GPUs 收到 trainer lease 必须 fail-fast。

FSDP2 Trainer

TrainerCoordinatorActor 汇总自动分配到 shared_gpus 的 ranks，建立 rank/world size 和稳定通信组；TrainerRankActor 已接入 Fsdp2TrainerBackend adapter。真实 FSDP2 执行依赖可加载模型、trainer.checkpoint_dir 与多 rank rendezvous/store endpoint；queue ack 必须晚于 optimizer step 成功。

vLLM Rollout

RolloutManagerActor 选择 prompt 与 target policy version，分发到 rollout DP replicas。每个 RolloutReplicaControllerActor 按 TP 组持有 rollout_gpu_i custom resources，并通过 VllmRolloutBackend adapter 激活权重和生成 response。

SampleQueueActor

样本 lifecycle owner，维护 pending、reserved、acked、dropped、failed。它执行 TTL、policy lag、queue 水位、ObjectRef 背压和去重。

WeightRegistryActor

权重版本 owner，区分 REGISTERED 和 ACTIVE_GLOBAL。trainer 注册 artifact 不代表 rollout 已经切换；只有所有必要 rollout workers ack 目标版本后才能全局 active。

WeightTransferPlanner

独立的权重传输模块。它根据 weight_transfer.method、rollout replica GPU 集合和 trainer rank 映射生成 per-replica WeightTransferPlan，把 objectref、小心的本地 reshard、artifact hydrate 分开。

RewardActorPool

负责 rule reward、model reward 或后处理。它不拥有训练 loop，只把 reward 或 reward ref 附到样本数据路径中。

MetricsActor / health sink

接收指标、事件和 tracing payload。高频 token 级明细应先本地聚合，低频事件直接上报。Controller 依据连续阈值而不是单点指标做降级。

权重传输模块

FSDP2 每个 optimizer step 之后，trainer/exporter 先发布新的 WeightMeta 和 artifact/manifest； 随后 WeightTransferPlanner 为每个 rollout DP replica 生成 WeightShardSource。 这个模块不拥有训练 loop，也不写 registry 状态，只决定“这个 replica 从哪里 materialize 目标版本”。

objectref

显式实验路径。权重对象或 shard refs 进入 Ray object store，rollout 侧按 ray_object_ref source 拉取。适合小模型、fake backend 和调试；真实大模型会给 object store、序列化和 fan-out 带来压力。

shared_gpu_reshard

默认路径中的 shared GPU 分支。目标 rollout TP group 的 GPU 全部也是 trainer ranks 所在 GPU；训练窗口结束后，lease 切回 rollout，backend 把本地 FSDP2 shard 或 CPU standby state reshard 成 vLLM TP layout。

artifact_pull

默认路径中的 rollout-only 分支。没有 trainer-resident 权重的 rollout-only GPU 从 artifact_uri / manifest_uri hydrate 需要的 vLLM shard，避免把整份权重通过 ObjectRef 广播。

配置入口是 weight_transfer.method：默认 locality_aware_checkpoint，也可切到 objectref。 当存在 rollout_only_gpus 时，locality-aware 路径必须允许 artifact pull；否则这些 GPU 没有任何本地 trainer shard 可重组。

Ray actor 清单

这里按当前设计列出所有 actor 或 actor-like role。关键约束是：rollout 和 trainer execution actors 是独立故障域，集合内部 GPU 不重复，集合之间可以通过 shared_gpus overlap。 长生命周期 rollout/train actor 不用 Ray num_gpus=1 表达互斥，而是用 role-scoped logical resources 加 GpuLeaseManagerActor lease gate。 dry-run 会输出 ray_launch_plan：其中 node_custom_resources 同时声明 shared GPU 的 rollout_gpu_i 与 train_gpu_i，rollout replica actor 按 TP 组占用 rollout_gpu_i custom resources，所有长生命周期 actor specs 保持 num_gpus=0。

Actor / role Ray 资源 职责 主要交互
ControllerActor CPU actor 训练主循环、模式 FSM、GPU lease 编排、train trigger、背压和恢复策略。 创建并调用 lease manager、rollout manager、trainer coordinator、queue、registry、metrics；把异常归一化为 health event。
GpuLeaseManagerActor CPU actor 每张物理 GPU 的 active role、holder、lease epoch、失败状态和 fail-fast CUDA gate。 接受 Controller/manager/coordinator 的 lease request；拒绝 rollout-only GPU 上的 trainer lease；上报 Metrics。
RolloutManagerActor CPU actor 全局 rollout 生命周期、input backlog、replica 选择、target policy version、in-flight 跟踪、queue 背压响应、全局权重切换暂停。 接收 dataloader prompts；在 output queue 未到 high watermark 且 replica 有 in-flight capacity 时持续 pump rollout；读 WeightRegistryActor 并调用 rollout replica controllers。
RolloutReplicaControllerActor TP group logical rollout GPU resources 每个 rollout DP replica 一个；按 TP 组占用 rollout_gpu_i custom resources，构造 vLLM backend adapter，管理权重激活、drain/offload/wake 和 replica failure。 接收 RolloutManagerActor 请求；协调多个 TP workers；以 replica 为单位 ack activation；执行 CUDA 前校验 rollout leases。
RolloutWorkerActor num_gpus=0 TP rank role 每个 vLLM TP rank 一个；不申请 Ray GPU token，维护 TP rank 元数据和未来 worker/shard 边界。 CUDA-facing 行为必须通过 rollout lease 与 replica/backend gate；不单独抢占 rollout_gpu_i resource。
TrainerCoordinatorActor CPU actor 汇总自动分配到 shared_gpus 的 trainer ranks，管理 rank mapping、world size、group_epoch、train window、batch reservation 与错误归一化。 从 SampleQueueActor reserve/ack/release batch；协调 TrainerRankActor；rank0/export 后注册权重。
TrainerRankActor logical train GPU resource FSDP2 rank，管理 model shard、optimizer/scheduler/RNG/scaler，执行 micro-batch forward/backward、optimizer step、checkpoint shard。 执行 CUDA 前校验 trainer lease；由 TrainerCoordinatorActor 下发 rendezvous 和 batch refs；rank0/exporter 产出权重。
SampleQueueActor CPU actor 样本队列、dedupe、TTL、policy lag guard、ObjectRef 背压、reservation lease、drop/defer/ack 状态。 接收 rollout sample refs；向 trainer 提供 train batch reservation；上报 drop rate、depth、object store pressure。
WeightRegistryActor CPU actor 权重版本注册、状态机、latest healthy 查询、activation ack、rollback/deprecated 标记。 接收 trainer export 后的 WeightMeta；供 rollout coordinator 选择版本；等待 rollout workers ack 后标记 ACTIVE_GLOBAL。
WeightTransferPlanner CPU module 生成 per-version/per-replica 的权重传输计划，不承载大 tensor。 读取 WeightMeta、ResolvedGpuPlan 和 weight_transfer.method；输出 ray_object_ref、shared_gpu_reshard 或 artifact_pull source。
RewardActor / RewardActorPool CPU actor；未来可选 GPU reward function、rule reward、model reward 或样本后处理。 被 rollout path 调用；结果写入 SampleRecord 或 reward ref；指标进入 MetricsActor。
MetricsActor CPU actor 指标、health events、trace 聚合和阈值输入。 接收所有 actor/role 的事件；供 Controller 判断 degraded、paused、recovery。
RolloutReplicaControllerActor TP path CPU group coordinator 当 vLLM tensor_parallel_size > 1 时，以 replica 为单位管理 TP 通信、sleep/wake/offload 和失败恢复。 聚合多个 RolloutWorkerActor；对 RolloutManagerActor 暴露一个 logical rollout endpoint。

协议与状态

SampleRecord

必须包含 sample_id、policy_version、prompt、response、tokens、logprobs、reward。扩展字段包括 request_id、weight_checksum、finish reason、TTL、token counts、old logprobs、worker metadata；partial rollout 样本还要带 token span 级 policy_segments。

WeightMeta

必须包含 version_id、创建时间、model path、format 和 checksum。模型与 checkpoint path 不要求声明 source type；默认大权重不经 Ray object store 广播。

WeightTransferPlan

per-version/per-replica 控制面协议，记录 objectref、shared_gpu_reshard 或 artifact_pull source。它只带 source metadata，不携带真实 tensor。

TrainBatch

trainer 消费侧聚合协议，记录 sample refs、版本范围、版本直方图、sequence/token 数、reservation owner 和 lease 过期时间。ack 晚于 optimizer step 成功。

Health events

最小事件集覆盖 rollout stale weight、queue backpressure、sample TTL/policy lag drop、trainer OOM、weight distribution failure、shared GPU toggle timeout、comm group rebuild 和 object store pressure。

Shared GPU lease toggle 状态

ROLLOUT_ACTIVE ROLLOUT_DRAINING ROLLOUT_OFFLOADING_CPU TRAIN_HYDRATING_GPU TRAIN_READY_BARRIER TRAIN_ACTIVE TRAIN_DRAINING TRAIN_OFFLOADING_CPU ROLLOUT_WAKING_GPU ROLLOUT_READY_BARRIER

正常 toggle 不销毁 FSDP2 process group。通信组生命周期长于一次 train window，rank mapping 和 rendezvous metadata 保持稳定； 只有 GPU/rank failure、NCCL error、作业恢复或 shutdown 才 rebuild，并生成新的 comm_epoch。 rollout_only_gpus 不允许获得 trainer lease。

关键约束与风险

  • GPU lease：GpuLeaseManagerActor 是 active-role source of truth。role 绕过 lease token 执行 CUDA 会破坏互斥。
  • Topology gate：rollout_only_gpus 表示只支持 rollout lease；这类 GPU 的 trainer lease 请求必须返回 unsupported role。
  • bounded staleness：standalone_hybrid 允许旧权重样本，但必须受 max_policy_lag、TTL、drop/degrade 策略约束，不能演化成无界 async。
  • 权重状态：REGISTERED 只代表 artifact 可用，不代表 rollout 已经服务该版本。全局恢复 prompt 前必须在当前 rollout lease epoch 下收齐 activation ack；激活失败的目标版本必须标记为 FAILED。
  • 权重传输：objectref 只应作为显式配置的实验路径；默认 locality_aware_checkpoint 要让 shared GPU 本地 reshard，并让 rollout-only GPU 从 artifact/manifest hydrate。
  • queue ack：trainer 失败时不能丢样本。queue ack 必须在 optimizer step 成功之后；失败路径 release reservation 或标记不可重试。
  • process group：高频 toggle 不应 destroy/reinit FSDP2 process group，否则正常调度路径会变成容易 deadlock 的路径。
  • v0.1 范围：不加入多机 Ray、Kubernetes、Slurm、SSH launcher；rollout TP 通过 RolloutReplicaControllerActor 管理，不能让 TP group 横跨 rollout-only/shared 生命周期区域。
