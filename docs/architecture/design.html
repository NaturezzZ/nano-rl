架构总览

nano-rl v0.1 的核心目标是做一个“小而全”的 RL 框架：trainer 后端目标是 PyTorch FSDP2， rollout 后端目标是 vLLM，执行层固定为单机 Ray-native actor runtime。控制器拥有 loop 语义； trainer、rollout、reward、queue、weight registry 和 metrics 都是可替换后端或服务边界。

YAML-first Ray-native FSDP2 trainer vLLM rollout policy_version accounting bounded staleness single-machine v0.1

Control plane

main.py 读取 YAML，校验并归一化成 LaunchConfig。Ray Driver 初始化 runtime，创建 ControllerActor，由 controller 驱动模式 FSM、train window、rollout 节奏和故障恢复。

Resource plane

每张物理 GPU 对应一个 GpuSlotActor(num_gpus=1)。slot mode 为 rollout_only、hybrid 或 idle；hybrid slot 在 rollout role 与 trainer rank role 之间显式 toggle。

Data plane

rollout 样本通过 Ray ObjectRef 进入 SampleQueueActor，trainer 通过 reservation 消费。权重通过 WeightMeta 指向 HDFS/HDFS-FUSE artifact，不把大权重放进 Ray object store。

图中实线表示控制或数据调用关系，虚线表示由 GpuSlotActor 托管的 slot 内 role。真正申请 Ray GPU token 的只有 GpuSlotActor。

SVG rollout 全流程图

下面把一次 rollout 从 prompt 分发到样本入队、训练消费、权重发布和全局激活串起来。fully_sync 下所有 GPU 都是 hybrid， 每轮 rollout 后整体切 train；standalone_hybrid 下只 drain hybrid slots，rollout_only slots 在背压与 policy lag guard 下继续生成。

运行模式

用户 YAML mode 内部 canonical mode GPU slot 形态 rollout/train 语义
collocated fully_sync 全部 GPU 都是 hybrid；示例为 8 个 hybrid、0 个 rollout_only。 全局 barrier：同一版本权重完成 rollout 后，全体 slot 切 train，再发布下一版本。max_policy_lag=0。
disaggregated standalone_hybrid 同时存在 rollout_only 与 hybrid；示例为 4 个 rollout_only、4 个 hybrid。 rollout_only 持续生成；hybrid 在训练窗口 drain 后切到 trainer ranks。允许 bounded staleness，例如 max_policy_lag=2。

sync / async 不是用户入口别名；fully_sync / standalone_hybrid 也不能直接作为用户 YAML mode。 这些内部名只应该出现在 resolved config、日志和 FSM 中。

组件设计

main.py 与配置加载

用户入口只负责读取 YAML、处理 run.intent、归一化 mode、校验 artifact 和资源拓扑、输出 resolved config，并生成不可变 LaunchConfig。训练参数不应拆成命令行覆盖面。

Ray Driver

负责 ray.init、单机资源校验、placement group 规划和创建 ControllerActor。v0.1 不加入 Kubernetes、Slurm、SSH 或多节点 Ray launcher。

ControllerActor

唯一 loop 语义 owner。它决定何时发 prompt、何时开 train window、何时限流、何时进入 degraded 或 paused，并统一解释 actor 异常为 health event。

Mode FSM

维护 BOOTSTRAP、FULLY_SYNC_ACTIVE、STANDALONE_HYBRID_ACTIVE、DEGRADED_SYNC、PAUSED 和 STOPPED。FSM 只处理 canonical mode。

GpuSlotActor

每张 GPU 一个 slot actor，独占 Ray num_gpus=1。它管理 slot 内 rollout/train role 的 lifecycle、CUDA residency、toggle、epoch 和 fail-fast active-role gate。

Hybrid toggle

默认策略是 swap_on_toggle。rollout -> train 时 drain generation、flush sample、释放 vLLM/KV cache、hydrate trainer state；train -> rollout 时完成安全点、发布权重、offload trainer、唤醒 rollout。

FSDP2 Trainer

TrainerCoordinatorActor 汇总 hybrid slots，建立 rank/world size 和稳定通信组；TrainerRank role 执行 PPO-like forward/backward、optimizer step、checkpoint/export。queue ack 必须晚于 optimizer step 成功。

vLLM Rollout

RolloutCoordinatorActor 选择 prompt 与 target policy version，分发到 active rollout roles。RolloutWorker 使用 vLLM 生成 response、tokens 和 PPO 所需 old logprobs。

SampleQueueActor

样本 lifecycle owner，维护 pending、reserved、acked、dropped、failed。它执行 TTL、policy lag、queue 水位、ObjectRef 背压和去重。

WeightRegistryActor

权重版本 owner，区分 REGISTERED 和 ACTIVE_GLOBAL。trainer 注册 artifact 不代表 rollout 已经切换；只有所有必要 rollout workers ack 目标版本后才能全局 active。

RewardActorPool

负责 rule reward、model reward 或后处理。它不拥有训练 loop，只把 reward 或 reward ref 附到样本数据路径中。

MetricsActor / health sink

接收指标、事件和 tracing payload。高频 token 级明细应先本地聚合，低频事件直接上报。Controller 依据连续阈值而不是单点指标做降级。

Ray actor 清单

这里按当前设计列出所有 actor 或 actor-like role。关键约束是：同一张物理 GPU 不能同时存在两个都声明 num_gpus=1 的 Ray actor。 TrainerRank 和 RolloutWorker 可以先实现为 GpuSlotActor 内部对象，也可以是 slot 托管的轻量 child actor，但不应再申请独立 GPU token。

Actor / role Ray 资源 职责 主要交互
ControllerActor CPU actor 训练主循环、模式 FSM、slot 编排、train trigger、背压和恢复策略。 创建并调用 slot、coordinator、queue、registry、metrics；把异常归一化为 health event。
GpuSlotActor num_gpus=1 heavy actor 一张物理 GPU 的唯一 owner；管理 rollout/train role 生命周期、CUDA device、active role、toggle 和失败状态。 接受 Controller/coordinator 的 phase request；托管 RolloutWorker 和/或 TrainerRank role；上报 Metrics。
RolloutCoordinatorActor CPU actor prompt 分发、worker 选择、target policy version 选择、in-flight 跟踪、queue 背压响应、全局权重切换暂停。 读 WeightRegistryActor，调用 slot-hosted rollout role，向 SampleQueueActor 提交样本 metadata/ref。
RolloutWorker role slot 内 GPU role；不独立申请 GPU token 运行 vLLM engine，激活权重，生成 response/tokens/old logprobs，drain in-flight，释放 KV cache/CUDA residency。 被 GpuSlotActor gate；接收 RolloutCoordinatorActor 请求；调用 reward 或提交 sample refs。
TrainerCoordinatorActor CPU actor 汇总 train-capable hybrid slots，管理 rank mapping、world size、group_epoch、train window、batch reservation 与错误归一化。 从 SampleQueueActor reserve/ack/release batch；协调 TrainerRank roles；rank0/export 后注册权重。
TrainerRank role slot 内 GPU role；不独立申请 GPU token FSDP2 rank，管理 model shard、optimizer/scheduler/RNG/scaler，执行 micro-batch forward/backward、optimizer step、checkpoint shard。 被 GpuSlotActor gate；由 TrainerCoordinatorActor 下发 rendezvous 和 batch refs；rank0/exporter 产出权重。
SampleQueueActor CPU actor 样本队列、dedupe、TTL、policy lag guard、ObjectRef 背压、reservation lease、drop/defer/ack 状态。 接收 rollout sample refs；向 trainer 提供 train batch reservation；上报 drop rate、depth、object store pressure。
WeightRegistryActor CPU actor 权重版本注册、状态机、latest healthy 查询、activation ack、rollback/deprecated 标记。 接收 trainer export 后的 WeightMeta；供 rollout coordinator 选择版本；等待 rollout workers ack 后标记 ACTIVE_GLOBAL。
RewardActor / RewardActorPool CPU actor；未来可选 GPU reward function、rule reward、model reward 或样本后处理。 被 rollout path 调用；结果写入 SampleRecord 或 reward ref；指标进入 MetricsActor。
MetricsActor CPU actor 指标、health events、trace 聚合和阈值输入。 接收所有 actor/role 的事件；供 Controller 判断 degraded、paused、recovery。
RolloutGroupActor（未来条件） CPU/group coordinator；slot 仍持 GPU token 当 vLLM tensor_parallel_size > 1 时，以 group 为单位管理 TP 通信、sleep/wake/offload 和失败恢复。 聚合多个 GpuSlotActor；对 RolloutCoordinatorActor 暴露一个 logical worker。v0.1 默认不启用。

协议与状态

SampleRecord

必须包含 sample_id、policy_version、prompt、response、tokens、logprobs、reward。扩展字段包括 request_id、weight_checksum、finish reason、TTL、token counts、old logprobs 和 worker metadata。

WeightMeta

必须包含 version_id、创建时间、source type、model URI、format 和 checksum。artifact 来源只接受 hdfs_uri 或 hdfs_fuse_path，不把大权重经 Ray object store 广播。

TrainBatch

trainer 消费侧聚合协议，记录 sample refs、版本范围、版本直方图、sequence/token 数、reservation owner 和 lease 过期时间。ack 晚于 optimizer step 成功。

Health events

最小事件集覆盖 rollout stale weight、queue backpressure、sample TTL/policy lag drop、trainer OOM、weight distribution failure、hybrid toggle timeout、comm group rebuild 和 object store pressure。

Hybrid slot toggle 状态

ROLLOUT_ACTIVE ROLLOUT_DRAINING ROLLOUT_OFFLOADING_CPU TRAIN_HYDRATING_GPU TRAIN_READY_BARRIER TRAIN_ACTIVE TRAIN_DRAINING TRAIN_OFFLOADING_CPU ROLLOUT_WAKING_GPU ROLLOUT_READY_BARRIER

正常 toggle 不销毁 FSDP2 process group。通信组生命周期长于一次 train window，rank mapping 和 rendezvous metadata 保持稳定； 只有 slot/rank failure、NCCL error、作业恢复或 shutdown 才 rebuild，并生成新的 comm_epoch。

关键约束与风险

  • GPU ownership：GpuSlotActor 是唯一申请 num_gpus=1 的 actor。role 绕过 slot owner 执行 CUDA 会破坏 hybrid 安全性。
  • bounded staleness：standalone_hybrid 允许旧权重样本，但必须受 max_policy_lag、TTL、drop/degrade 策略约束，不能演化成无界 async。
  • 权重状态：REGISTERED 只代表 artifact 可用，不代表 rollout 已经服务该版本。全局恢复 prompt 前必须收齐 activation ack。
  • queue ack：trainer 失败时不能丢样本。queue ack 必须在 optimizer step 成功之后；失败路径 release reservation 或标记不可重试。
  • process group：高频 toggle 不应 destroy/reinit FSDP2 process group，否则正常调度路径会变成容易 deadlock 的路径。
  • v0.1 范围：不加入多机 Ray、Kubernetes、Slurm、SSH launcher，也不支持 rollout TP > 1，除非重新打开设计。
